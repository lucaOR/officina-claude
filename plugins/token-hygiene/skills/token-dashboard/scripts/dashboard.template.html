Data notes

  • The current generation counts one API response once: transcript records are grouped by message.id, and a response is closed only by a new id, a compaction boundary, or end of transcript. Older generations are frozen and must never be summed with this one — .v2 also split a response whenever a parallel tool call's tool_result landed between its records (+6.3% billed, +8.3% responses), and the unsuffixed legacy CSVs double-count ~2.1x.
  • A turn is one assistant API response, not one user message; each tool round-trip is its own turn.
  • The per-class split of cache replay is a residency heuristic — the transcript does not tag which cached bytes belong to which class. Output and cache-creation attribution is exact, and the replay total is exact; only its division across classes is modelled.
  • Scope is this project directory only. Sessions predating the hook, or whose transcripts rotated out before backfill, are absent.
